# Visual-JEV submission benchmark protocol

This protocol governs submission tables generated by `scripts/generate_submission_tables.py`.
The fixed checkpoint for full-split evaluation is
`experiments/visual_jev_v3_paper/checkpoints/v3_full.pt` (seed 20260928,
controlled COCO training). Its exact file SHA256 is recorded in every manifest
and result. No training or threshold/calibration fitting is performed on the
new evaluation splits. A different checkpoint requires a different result
directory and refreshed checkpoint provenance.

## Terminology and evidence boundaries

| Canonical term | Meaning and permitted use |
|---|---|
| Visual-JEV | Our adapter and candidate decision head |
| Visual Jev | Concurrent official answer-SFT model implementation |
| full benchmark protocol | Every instance in a named official split or native task; no sampling |
| matched protocol | The identical custom held-out examples/candidates used for our and official Visual Jev runs |
| controlled diagnostics | Custom COCO ablations and verified semantic pairs |
| sample/debug | Smoke tests or capped runs; excluded from main benchmark tables |
| validation accuracy | Score on an official validation split; never called test accuracy |

No mean across these protocols is reported. The prior `full_independent` profile
means full **training-feature manifests**, not a complete official test. Its
A-OKVQA 390, ScienceQA 984, IconQA 1838 and COCO 83 held-out examples are
custom partitions. The earlier 16-example smoke results and 80/128-example
controlled sets are diagnostic evidence only. Their real results remain
available, labelled by protocol, in matched/ablation/dependency tables.

Official Visual Jev indices 0/1/2 load the released root/seed1/seed2 answer-SFT
adapter variants. Their evaluation/candidate-permutation seed is fixed at
20260928. These recorded adapter comparisons do not supply training-seed
uncertainty for our Visual-JEV model and are not pooled with our training seed.

## Dataset and task registry

| Dataset | Scored source split/task | Metric and transformation |
|---|---|---|
| GQA | complete balanced test-dev (12578 questions) | Fixed train-only answer vocabulary, exact answer; OOV stays incorrect in full denominator. Candidate-constrained adaptation, not unrestricted generation. |
| SNLI-VE | official test (17901 hypotheses) | Original three classes, including neutral. All Flickr30K images required. No substitution with e-SNLI-VE. |
| TextVQA | official validation (5000 questions) | VQA leave-one-out consensus with official punctuation/digit/article rules. Candidate set comes from OCR 1--3-grams plus a declared fixed or train-only vocabulary. Gold answers never enter candidate construction. Candidate oracle ceiling is disclosed. |
| TallyQA | all 38589 test questions (26451 image groups in mirror) | Fixed counts 0--15; report all questions and simple/complex strata. No filtering by answer. |
| ScienceQA | whole official test (4241 questions) | Native choices, answer index. Hints allowed; lectures/solutions excluded. Intrinsically text-only examples receive a white blank input. Also report image-bearing and text-only strata separately. |
| A-OKVQA | official validation (1145 questions) | Native four-choice accuracy. Test 6702 questions has hidden labels and is not scored. |
| IconQA | entire official test choose_txt/select_txt task (6316 questions) | Native text-choice accuracy. Source test also has choose_img and fill_in_blank; those are separate tasks and recorded in excluded task counts. |
| AI2D | entire official test (3088 questions) | Native four choices and official target indices. |
| NLVR2 | official test-P, after image authorization | Binary choice; left/right image concatenation is disclosed as an adaptation. Public mirror access alone does not prove permission. |
| VSR | official random test (2195 statements) | Binary true/false; use original source labels and complete COCO references. |
| Winoground | all 400 official test groups, after access approval | Compute four raw image/caption scores. Official strict text, image and group scores; ties are failures. Softmax probabilities from different images are not compared. |
| SugarCrepe++ | entire released evaluation suite, 4757 triplets, all five categories | Strict ITT requires both positive captions to exceed the negative. Keep category breakdowns. HF storage split `train` is explicitly named and is not represented as official test. Original SugarCrepe is never substituted. |

Registry sources and Hugging Face mirror IDs are in `scripts/submission_benchmarks.py`.

The grouped TallyQA mirror has also been checked against the author's pinned
`tallyqa.zip` test annotations: every question/answer/simple-flag/source tuple
matches exactly as a multiset (38589 questions, 22991 simple and 15598 complex).
The source commit and ZIP SHA256 are recorded in `official_annotation_audit.json`.
Reproduce this independent check with `scripts/audit_submission_sources.py`.

The same script verifies all 4757 SugarCrepe++ triplets against the author's
five pinned category files: category/image/two-positive/negative tuples match
exactly, with zero missing or additional entries. Its source-file SHA256 values
are saved in the suite's `official_annotation_audit.json`.

Mirrors are pinned to repository commit SHA before download; exact source files
and their SHA256 hashes are stored in `download.json`. Dataset fingerprint,
source row count and task row count are distinct fields. Counts stated above
are protocol targets; actual availability and completion are in the manifests
and `experiments/tables/submission/main_full_benchmark.{csv,md,tex}`.

## Access and completeness

Downloads use ordinary public access or the user's existing authorized Hub
credentials. The workflow does not accept terms, request access, obtain new
credentials, or bypass a gated repository. Winoground access failure is saved
as a blocked manifest. SNLI-VE image resources must come from an authorized
Flickr30K collection. NLVR2 requires researcher registration/permission at
the official site; `--nlvr2-authorized` is an explicit user attestation of that
already satisfied condition. Dataset cards' declared licenses and original
source URLs are saved; mirrors do not enlarge original image rights. Local
research downloads are not redistributed in the submission package.

Any missing/corrupt required image, duplicate UID, hidden label or invalid
candidate row blocks the **whole declared split/task**. The pipeline retains
`resource_gaps.json`, complete annotations and exact recovery commands. It
never reports an accuracy over only the images that happened to download.
Intrinsic ScienceQA text-only items are a source-defined modality, not a
missing-resource subset. IconQA native task eligibility is declared in advance.
No evaluator uses dataset select/shuffle/take or a max-samples/train-cap option.

The fixed checkpoint uses its original frozen feature boundary: native
pre-merger spatial groups are mean-pooled, candidate templates use right
padding, and no new text truncation is introduced in `encode_candidates`.
Source image preprocessing retains the checkpoint-compatible processor bounds.

## Manifest and result contract

Each `data/submission_benchmarks/<dataset>/manifest.json` records:
dataset_name, repo/source, split, N, N_source, revision, fingerprint,
is_true_test, public_labels, seed, checkpoint_sha256, candidate manifest hash,
license/access metadata, excluded task counts, missing image count, status
and reason. The SHA256 of the checkpoint file, not just the model name, is
authoritative.

The evaluator saves ordered per-instance raw scores to `predictions.jsonl`.
Resume identity binds checkpoint hash, candidate manifest hash, backbone and
control setting. A changed identity is rejected. Exact ordered UID coverage
must equal the complete manifest before `result.json` is marked complete.
Partial progress is `status.json`, never an official score. No failed or
partial result enters a table; a cell remains `--`.

Classification metrics use one image--question instance as the experimental
unit. Candidate-index macro-F1 is secondary and is not treated as a semantic
answer-class F1 for variable K. No new significance tests or confidence claims
are inferred from accuracy alone. Training-seed uncertainty is unavailable for
the fixed-checkpoint full benchmark runs unless separately executed.

## Visual dependency and latency

Original/blank/wrong use every row of the declared split. Wrong images follow
a deterministic cyclic shift to an image with different file-content SHA256; repeated image rows
are skipped only while selecting the wrong-image **control**, never while
selecting evaluation examples. The wrong image may still support the same
answer, so this is diagnostic. Blank uses the original image canvas size.
Verified semantic counterfactual, pair-both and pair-flip remain `--` when no
verified paired annotation exists. Available controlled COCO pair results
retain their custom protocol and 48-pair denominator.

The evaluator can verify earlier control predictions and recompute only those
whose wrong-image content was identical. Use `--repair-wrong-controls --controls`;
the original prediction file is backed up, primary scores are unchanged, and
the result records the verification flag and repair count. Unverified full-split
wrong-image numbers are withheld from generated tables.

The evaluation time per row includes original/control passes when enabled,
and repeated-image feature reuse where applicable. It is saved for operational
traceability and is not a live inference speed comparison.

Recorded row times exclude later wrong-control verification/recomputation;
those extra repair passes must not be treated as included latency.

Official Visual Jev's existing model-run times exclude prepare_group. The latency table names
these boundaries explicitly; do not pool them or claim a speedup from them.
Trainable params exclude the frozen backbone.

## Reproducible commands

One-command recovery (manual access/image prerequisites must already be satisfied):

```bash
.venv/bin/python scripts/resume_submission_benchmark.py snli_ve --flickr30k-root data/flickr30k-images
.venv/bin/python scripts/resume_submission_benchmark.py winoground
.venv/bin/python scripts/resume_submission_benchmark.py nlvr2 --nlvr2-authorized
```

Each command prepares the whole declared split, refuses partial accuracy,
evaluates only a complete ready manifest and refreshes evidence-based tables.
Optional `--paper-root /mnt/c/.../paper-project` copies tables/report/protocol
to an existing paper project. No access terms or authorization are silently accepted.

```bash
cd ~/projects/Open-Jev
.venv/bin/python scripts/submission_benchmarks.py prepare --fetch-images
.venv/bin/python scripts/evaluate_submission_benchmarks.py --controls
.venv/bin/python scripts/generate_submission_tables.py
```

Full vocabulary preparation (all training rows, no evaluation labels):

```bash
.venv/bin/python scripts/submission_benchmarks.py build-vocab --dataset gqa
.venv/bin/python scripts/submission_benchmarks.py prepare --datasets gqa --refresh
.venv/bin/python scripts/evaluate_submission_benchmarks.py --datasets gqa --controls
.venv/bin/python scripts/submission_benchmarks.py build-vocab --dataset textvqa
.venv/bin/python scripts/submission_benchmarks.py prepare --datasets textvqa --refresh
.venv/bin/python scripts/evaluate_submission_benchmarks.py --datasets textvqa --controls --output-root experiments/results/submission_full_textvqa_train_vocab
```

The GQA and TextVQA vocabulary scoring can be expensive: batching candidates
changes memory usage, never the candidate set or split size. Do not truncate
the vocabulary based on evaluation answers. The fixed OCR-constrained TextVQA
protocol and the train-vocabulary protocol must use different result roots.

After obtaining Flickr30K images through its official authorized route, place
or extract them in `data/flickr30k-images/` and run:

```bash
.venv/bin/python scripts/submission_benchmarks.py prepare --datasets snli_ve --refresh --flickr30k-root data/flickr30k-images
.venv/bin/python scripts/evaluate_submission_benchmarks.py --datasets snli_ve --controls
```

After Winoground access is approved on the official dataset page, authenticate
using the user's own token (`.venv/bin/hf auth login`; do not put a token in
logs), then run:

```bash
.venv/bin/python scripts/submission_benchmarks.py prepare --datasets winoground --refresh
.venv/bin/python scripts/evaluate_submission_benchmarks.py --datasets winoground
```

After NLVR2 image terms/registration are satisfied:

```bash
.venv/bin/python scripts/submission_benchmarks.py prepare --datasets nlvr2 --refresh --nlvr2-authorized
.venv/bin/python scripts/evaluate_submission_benchmarks.py --datasets nlvr2 --controls
```

Previously available independent full **training** can be reproduced without
reducing training size (these commands retain the custom held-out protocol):

```bash
.venv/bin/python run_independent_datasets.py --train-cap 0 --result-root experiments/results/independent_datasets_full_reproduction --resume
```

New full benchmark evaluation uses existing checkpoints without fitting.

`bash scripts/run_submission_full_training.sh` reproduces the historical full
training-feature experiment without a train cap; it is not run automatically
and its custom held-out metrics remain outside the official full-split table.
New dataset-specific training or a mixed model is future work; it must retain
official train/evaluation boundaries and receive its own result provenance.

## Table and manuscript generation

Five CSV/Markdown/LaTeX table sets are written to `experiments/tables/submission/`:
main_full_benchmark, matched_visual_jev, visual_dependency, latency_params,
ablation. `table_sources.json` maps rows to real result files and source hashes.
Legacy JSON is wrapped with source SHA256 into lossless `result.json` records
under `experiments/results/submission_legacy/`; protocol labels prevent it from
entering the main official-split table. `legacy_result_audit.json` records all
existing result.json exclusions from the main table. `pending_benchmarks.json`
records remaining gaps and commands.

The manuscript's Experiments section includes these generated LaTeX tables.
Abstract/introduction/conclusion call the earlier custom experiments controlled
or matched diagnostics and avoid treating their counts as official benchmark
coverage. Main evidence, controlled evidence and incomplete measurements have
separate table references. Author review of task comparability and data/image
licenses remains part of preparing the actual submission.
